# 牙医 AI 助理 设计文档

> 面向**牙医**的工作流助手，重点覆盖**病历与治疗计划**和**术后随访与口腔健康教育**两条主线。
> 落地形态：基于 [`lark-cli`](../../README.md) 的 Agent Skill（见同目录 [`SKILL.md`](./SKILL.md)），复用飞书 Base/Docs/IM/Calendar/Task 能力。

---

## 1. 目标与非目标

### 1.1 目标
- 让牙医用**自然语言**完成日常重复工作：写病历、出治疗计划、发随访、推送护理须知。
- 数据**结构化沉淀**到飞书多维表格（Lark Base），便于后续统计与复用。
- 患者沟通走飞书 IM/邮件，统一渠道、可追溯。

### 1.2 非目标（V1 不做）
- **不做**临床诊断结论生成（仅辅助记录与模板化建议，最终诊断由医生确认）。
- **不做**医保结算、收费、影像 AI 分析。
- **不做**面向患者直接对话的智能客服（V2 再考虑）。

---

## 2. 用户与场景

### 2.1 主要用户
- **牙医**（全科 / 修复 / 正畸 / 牙周 / 种植）。

### 2.2 核心场景

| 场景 | 触发方式 | 期望产出 |
|------|---------|---------|
| 新建患者档案 | "登记一个新患者，张三，35 岁，主诉右下后牙冷热痛" | Base 中新建一行患者记录 |
| 写本次就诊病历 | "给张三记一次复诊：26 牙做了根管预备，X 光见……" | SOAP 结构化病历，写入 Base + 关联到患者 |
| 出治疗计划 | "给张三出一份 26 根管+全瓷冠的治疗方案" | 治疗计划飞书文档（分阶段、价目、风险告知） |
| 术后随访 | "拔牙后第 3 天给李四发个随访" | 飞书 IM 推送随访问卷 + Task 跟进未回复者 |
| 口腔健康教育推送 | "正畸患者第 1 个月护理要点发给王五" | 模板化护理消息（图文）+ 复诊提醒日程 |

## 3. 功能模块

```
┌────────────────────────────────────────────────────────┐
│                    Dentist (CLI / Chat)                │
└──────────────────────────┬─────────────────────────────┘
                           │  自然语言
                ┌──────────▼──────────┐
                │   Dental Assistant   │  ← Skill (Markdown 指令集)
                │   (Agent + LLM)      │
                └──┬────┬────┬────┬────┘
                   │    │    │    │
            ┌──────▼┐ ┌─▼──┐ ┌▼──┐ ┌▼────┐
            │ Base  │ │Doc │ │IM │ │ Cal │  ← lark-cli 现有 Skills
            │患者库 │ │方案│ │随访│ │复诊 │
            └───────┘ └────┘ └───┘ └─────┘
```

### 3.1 病历与治疗计划

- **患者档案（Base）**：基础信息、过敏史、既往史、家庭医生备注。
- **就诊记录（Base，关联患者）**：每次就诊一行，SOAP 四段式。
- **治疗计划（Docs）**：从模板生成飞书文档，分阶段列出治疗步骤、预计费用、风险告知、知情同意位。
- **影像/照片**：作为附件挂在就诊记录行（V1 仅做链接，不做识别）。

### 3.2 术后随访与口腔健康教育

- **随访任务（Task）**：术后 D+1 / D+3 / D+7 自动建任务并触达。
- **随访问卷（IM 卡片）**：疼痛指数、出血、肿胀等结构化选项，回填到 Base。
- **教育内容库（Docs/Wiki）**：按术式（拔牙、根管、种植、正畸、洁牙）建立模板。
- **复诊提醒（Calendar）**：自动按方案建议时间建议预约。

## 4. 关键对话流（示例）

### 4.1 记录一次就诊

```
医生：给张三记复诊。26 根管二次预备，工作长度 21mm，三根管，
       髓腔封 CWO，下周来充填。
助理：已记录到张三 #2026-05-12 复诊：
        - S: 自述冷热痛缓解
        - O: 26 根管二次预备，工作长度 21mm，三根管
        - A: 慢性牙髓炎，治疗中
        - P: 髓腔封 CWO，1 周后复诊充填
       已建议下周二 14:00 复诊，是否预约？[是 / 改时间]
```

### 4.2 术后随访

```
医生：李四今天 36 拔牙，给他安排随访
助理：已为李四创建随访计划：
        - D+1（明天 10:00）IM 推送术后须知
        - D+3 IM 推送疼痛/出血问卷
        - D+7 复诊预约
       问卷未回复将在 D+4 创建跟进任务。
```

## 6. 技术架构

### 6.1 落地形态
- **形态 A（V1 推荐）**：作为一个 `lark-cli` Skill — Markdown 指令集，AI Agent 读取后驱动现有 lark-cli 命令。零额外服务，靠 Agent 在本地协调。
- **形态 B（V2 可演进）**：抽出独立 Go 服务，复用 `internal/client` 调用飞书 OpenAPI，加上 Webhook 收患者回复。

### 6.2 关键依赖
| 依赖 | 用途 |
|------|------|
| `lark-cli base` | 患者档案、就诊记录、随访记录读写 |
| `lark-cli docs` | 治疗计划文档生成 |
| `lark-cli im` | 随访消息、教育内容推送 |
| `lark-cli calendar` | 复诊提醒 |
| `lark-cli task` | 跟进任务 |
| `lark-cli wiki` | 教育内容模板库 |

### 6.3 Skill 工作流（核心 5 个）
1. `register-patient`：自然语言 → 提取字段 → `base record create`
2. `record-visit`：转写 SOAP → 关联患者 → `base record create`
3. `make-treatment-plan`：模板填充 → `docs create` → 回写 doc_url
4. `schedule-followup`：根据术式选模板 → `task create` + `calendar event create` + 预约 IM 消息
5. `push-education`：从 Wiki 模板拉取 → `im message send`

## 7. 隐私与合规

- **本地优先**：患者姓名、电话、病史等 PII 只走授权用户的飞书租户，不出域。
- **最小授权**：Skill 默认只申请所需 scope（见 `skills/lark-shared/SKILL.md`）。
- **可审计**：所有写操作通过 lark-cli，飞书侧有审计日志。
- **AI 输出免责**：治疗计划文档首页固定加 "本计划由 AI 辅助生成，最终方案以医生面诊为准"。
- **数据保留**：建议在 Base 中区分活跃患者与归档（不同视图），不做自动删除。

## 8. 落地里程碑

| 里程碑 | 范围 | 验收 |
|--------|------|------|
| M1（本周） | Skill 骨架 + 病历/治疗计划工作流 | 一句话可创建患者+就诊记录，并生成治疗计划文档 |
| M2（+2 周） | 随访工作流 + 教育内容模板（5 类术式） | 拔牙患者能收到 D+1/D+3/D+7 三次触达 |
| M3（+1 月） | Base 看板（今日复诊、随访漏斗、月度量） | 牙医可在飞书 Base 看自己的工作量 |
| M4（V2） | 独立服务、Webhook 收患者回复、问卷自动归档 | 患者回复无需医生手动转录 |

---

## 9. 风险与开放问题

- **结构化 vs 自由文本**：SOAP 自动拆分可能不准 → V1 允许医生在 Base 中直接修正。
- **多医生协作**：同一患者多医生写病历 → 用 `dentist` 字段区分，Base 视图按医生过滤。
- **患者回复回流**：V1 患者在 IM 中回复后需医生人工点 "已回复"，V2 改 Webhook。
- **模板冷启动**：5 类术式模板需要医生先共建一次。
